# PV Circonomy 公共頁面結構

更新日期：2026-11-15

本文件定義 PV Circonomy 公共頁面的五種標準結構。Recycling 頁面是比例基準；其他公共頁面只能組合以下結構，不另建 route-specific 視覺骨架。共用樣式來源為 `app/components/review-home.css`。

## 1. 全屏

- 標準高度：`100svh`。
- 全屏內容可以是文字、媒體，或文字疊在媒體上。
- 媒體可使用圖片或影片；滿版媒體採 `object-fit: cover`。
- 內容不得因強制固定高度而被裁切；內容超過一頁時，section 可自然增高。
- 固定頂部導航與左側 section dots 浮在內容上方。
- Recycling Hero 是「文字疊在影片上」的現有範例。

## 2. 大左／小右

- 桌面比例：左側 `64%`、右側 `36%`。
- 左側與右側均可放置媒體或文字，不限定為左圖右字。
- 平板可使用現有 `56% / 44%` 過渡比例。
- 單側或雙側內容超過一頁高時，桌面左右兩側可以獨立垂直捲動。
- 獨立捲動區必須保留鍵盤操作、清楚的焦點狀態與可見的內容邊界；不得隱藏尚有內容的事實。
- 手機改為單欄自然文件流，不使用左右獨立捲動；兩側依資訊順序上下排列。
- Pricing 與 Delivery 是現有比例範例。

## 3. 上大／小下

- 標準比例：上方 `80svh`、下方 `20svh`。
- 上方固定為媒體，可使用圖片或影片，採滿版裁切。
- 下方固定為文字內容。
- 下方文字超過 `20svh` 時自然增高，不得裁切或建立狹窄的內嵌捲動區。
- 手機維持媒體在上、文字在下的自然排列。
- Traceability 是現有比例範例。

## 4. 左小／右大

- 桌面比例：左側 `43%`、右側 `57%`。
- 左右兩側均為文字內容。
- 單側或雙側內容超過一頁高時，桌面左右兩側可以獨立垂直捲動。
- 獨立捲動區必須能以鍵盤進入，並避免頁面與內層捲動互相搶奪。
- 手機改為單欄自然文件流，不使用左右獨立捲動。
- FAQ 是現有比例範例。

## 5. Footer

- Footer 必須融合於最後一個 section 的正常文件流。
- Footer 不建立額外的 `100svh` 畫面、獨立 scroll-snap 頁或空白下一屏。
- Footer 背景與最後一個 section 連續；可用分隔線區分資訊層級。
- 手機版須預留 Recycling help 與安全區域的底部空間。

## 組合與響應式規則

- 每個主要 section 使用 `scroll-snap-align: start`；長內容仍保留自然捲動。
- 首屏可使用全屏；一般雙欄內容依資訊權重選擇大左／小右或左小／右大；強媒體敘事使用上大／小下。
- 桌面獨立 pane 捲動只在內容確實超過可視高度時啟用，不能成為所有雙欄的預設。
- 手機版一律回到單一文件捲動，避免 nested-scroll trap。
- Footer 永遠融合在最後一個 section。
- 全站使用同一組 Public Header、Manrope 字體、黃色定位標記、方形控制元件與 Recycling help。
