# 回收報價、交付與訂單申請

## 已實作流程

1. Pricing 的 **Plan your delivery** 位於總價旁。按下後由伺服器驗證型號／輸入、讀取啟用價格、產生並儲存報價；效期為七天。
2. 自動帶入同頁 Delivery，顯示報價參考、處理費、到期時間與下載文件。報價與受限存取 token 暫存在瀏覽器 sessionStorage，重新整理可恢復；修改 Pricing 輸入會使待交付報價失效，需重新生成。
3. 客戶選 **Self-arranged delivery** 或 **Request pickup pricing**。
4. 按 **Place recycling order** 開啟預約表單：選日期、上午／下午、車型與車數；可新增分批。Pickup 另填美國取貨地址並計算運費。
5. 填寫聯絡資料、確認條件後按 **Submit recycling order request**。產生申請編號、狀態 pending；即占用所選時段容量。公司後台確認後保留容量，拒絕則釋放。

不自動派車或收款；客戶登入／Google 帳號尚未啟用，第一版支援持有效報價 token 的客戶提交申請。

## 初始營運設定

- 收貨地址：33380 Zeiders Road, Suite 103, Menifee, CA 92584, USA。
- 時區：America/Los_Angeles。日曆與所選時段明示此時區。
- 只有上午／下午標籤，未自行設定確切收貨鐘點。公司可在後台編輯標籤。
- 每個半天共用容量：1 Trailer 或 2 Truck；以 `Truck數 / Truck容量 + Trailer數 / Trailer容量 ≤ 1` 驗證混合車型。
- Pickup 與自行交付的容量池互相獨立，依使用者確認採相同初始容量。
- 初始每天開放、提前 1 天、顯示未來 60 天，皆為可在後台修改的初始設定。可設定不開放日期。
- pending 與 confirmed 都占用容量；拒絕申請釋放。不自行設定逾時自動釋放政策。

## 後台

入口：`/admin/delivery/`，價格管理頁有「交付與訂單」連結。使用既有公司 Microsoft 登入與 staff 權限。

可編輯地址、時區、開放星期、不開放日期、上午／下午文字、兩種車型容量、提前預約／可預約未來天數，以及 Truck／Trailer 的起始費、每英里費率與最低運費。設定採版本比對，防止覆蓋其他同事的更新。

訂單清單僅 staff 可讀取，含聯絡資訊、Pickup 地址、分批時段、金額與狀態。待處理申請可確認或拒絕，記錄操作公司帳號。確認表示公司接受訂單申請；不是系統向承運商下單或收款。

## Google Maps 自訂運費

請在 Vercel Production 設定 `GOOGLE_MAPS_API_KEY`，Google Cloud 專案需啟用 **Geocoding API** 與 **Routes API** 及相關帳務。使用伺服器 API key，請不要貼在聊天或前端程式。

- 取貨地址先以 US＋ZIP 限制進行 Geocoding，並驗證結果國家為 US。
- Google Routes 計算至收貨地址的 DRIVE 行車英里；不是直線距離，也不表示已取得承運商承諾或貨車限制路線。
- 自訂每車運費：`max(最低運費, 起始費 + 行車英里 × 每英里費率)`；依各批車型與車數加總。
- 自行安排運輸不計 PV Circonomy 運費，不代表客戶自己的運輸免費。
- 初始費率全部留空；空白不是零元。Google Maps key 或費率未設定時，允許提交 Pickup 待報價申請，標示運費待確認，不捏造運費。
- 自動報價啟用後，必須取得有效運費報價才能提交 Pickup；地址、批次或設定變更後需重新計算。
- 運費報價保留行車距離、設定版本、請求摘要與到期時間，到期不晚於回收報價。

## 資料與安全

新增 `pv_delivery_settings`、`pv_delivery_settings_history`、`pv_recycling_quotations`、`pv_freight_quotes`、`pv_recycling_order_requests`、`pv_delivery_rate_limits`。初次使用在 transaction／advisory lock 中建立，不修改舊型號或價格表。

- 報價型號由伺服器依 id 重新讀取來源，不採信客戶傳來的重量、單價或總額。
- 報價 token 隨機產生，資料庫僅存雜湊；沒有 token 或報價過期，不能用來預約或查運費。
- 預約採資料庫交易與 advisory lock，提交時重新檢查共用容量、設定版本與效期。
- Idempotency key 避免重試建立重複申請；相同 key 不允許改成另一份內容。同一報價最多一筆 pending／confirmed 申請；改用另一個 key 也不會重複占位，拒絕後才可重新申請。
- 設定及訂單管理需 staff session；寫入另檢查 Origin。公開客戶沒有訂單清單／聯絡資料讀取 API。
- 產生報價、查運費與建立申請均有持久化頻率限制。

## 驗證

`node tests/batch-quote.cjs` 驗證價格、係數與報價。

`node tests/delivery-integration.cjs` 必須使用獨立、可丟棄的本機 PostgreSQL，拒絕遠端資料庫。測試會清空測試庫相關表；請勿指向正式資料。預設連線為 127.0.0.1:55432 的 pv_delivery_test。

`PV_DELIVERY_BROWSER=1 node tests/delivery-integration.cjs` 另以 Playwright 檢查桌面與手機：前台產生儲存報價、帶入 Delivery、選時段與提交 PostgreSQL 申請。預設前台為 localhost:3105。Google 回應在測試中模擬，不產生 Google 費用、不建立真實派車。

PostgreSQL 測試涵蓋：偽造型號拒絕、共用容量、獨立 Pickup 池、併發超訂防護、重複提交、拒絕釋放容量、後台權限、設定衝突及運費公式。

## 全寬預約工作區與月曆

依最新指示，維持已完成的總價旁 Plan your delivery，不再次調整其位置。按 Place recycling order 後，Delivery 隱藏左側圖片，展開為全寬白底工作區：桌面左側報價／地址／聯絡表單，右側顯示月份月曆與上午／下午按鈕；手機改為月曆在上、表單在下。

月曆直接讀取後端可用容量，支援換月、日期選取、時段選取與方向鍵。日期與時段會同步至目前編輯的分批資料；多批共用容量仍以後端交易確認，前端會扣除其他尚未送出的批次選擇。不可用日期與時段停用。回到 delivery options 可收合工作區並保留輸入。送出後顯示申請結果，並收合回原本 Delivery 版面。

### 後台分工與美國時區

- `/admin/delivery/`：運輸管理，設定收貨地址、日曆、容量與運費；時區使用美國 50 州與 DC 的 IANA 下拉選單，伺服器同步限制可選值。日曆依地區規則處理夏令時間，洛杉磯預設與既有儲存設定保留。
- `/admin/orders/`：訂單管理，公司登入後可搜尋訂單／報價編號、客戶姓名、公司與 Email，依狀態篩選，每頁 25 筆；確認保留容量，拒絕釋放容量。已處理訂單不可重複變更。
- 訂單 API `/api/admin/orders/` 僅限公司帳戶，寫入驗證來源；查詢與回應不快取。現有訂單與資料表沿用。

## Pickup 條件、裝載與報價級距（2026-11-14）

Shipment scale 僅代表回收處理費級距，只保留 Truck／Trailer，不包含 Drop off；實際取貨車型在交付安排中獨立選擇，預設不由報價級距指定。Trailer 項目的總片數達到設定最低交付量時才適用按磅處理費；未達或門檻尚未設定時，按 Truck 每片處理費並明示原因。最低量留空且有 Truck 每車最多片數時，門檻採該數量＋1。既有已開立報價保留原版本；新報價由伺服器套用當時政策並保存。

運輸管理新增每車最大片數／毛重、Trailer 優惠最低交付量與 Pickup 附加服務費；數字不預填市場假設。空白為待設定，不當作零或無限載重。預約車輛容量不足時，前後台都拒絕該配置；限制不完整時標示公司覆核。Pickup 與自行送達的容量仍分開計算。

客戶勾選已拆下集中、妥善包裝、上棧板、膠膜、打包帶、整理與搬運協助、月台／堆高機、尾門及場址服務條件。報價的模組片數與原估重自動沿用，實際包裝毛重與棧板外長寬高、棧數可選填覆寫，原估值不被覆蓋。人工人數／工時可選填；未定工時或價格顯示待核價。固定服務費每訂單一次，整理與包材依棧數；人工費取最低出勤費及人時費較高者。無月台但有適用堆高機時不自動加尾門費。

資料完整、Google Maps 與車型費率已設定時，運費會在輸入後自動計算。明細列出處理費、基本運費、附加服務與已知費用小計；任何待確認項目不視為免費，也不宣稱完整總價。包裝尺寸、毛重或裝載上限不完整會列待確認。伺服器保存包裝／覆寫資料、費用明細；運費憑證綁定地址、車次、Pickup 條件及設定版本，資料異動須重算。

Delivery 僅提供 Email quotation，可寄送已計算的運費明細；提交後則可寄送保存的訂單申請明細。測試使用模擬寄信與模擬 Maps，不寄真實客戶郵件。提交 CTA 黃底黑字；付款 CTA 停用；進度圈依報價、安排、提交階段呈現黃底白字。取消訂單建議位於提交後的訂單狀態旁，尚未加入取消功能或自動釋放流程。
